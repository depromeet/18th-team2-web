# 작업 지침

## 1. 기본 원칙

- 모든 응답은 **한국어**로 합니다.
- 코드를 작성하기 전에 반드시 이 문서와 관련 컨벤션 파일을 먼저 읽습니다.
- 작업 범위를 벗어나는 변경(리팩터링, 스타일 정리 등)은 하지 않습니다.

## 2. 제안 먼저, 승인 후 실행

**탐색·분석 질문** (`어떻게 구현할까?`, `뭐가 문제일까?`)
→ 2–3문장 요약 + 트레이드오프 제시 → 사용자 승인 후 구현

**명확한 구현 요청** (`~를 추가해줘`, `~를 수정해줘`)
→ 바로 구현 (단, 파괴적 변경·외부 의존성 추가 시 먼저 확인)

**파괴적 변경이 필요한 경우** (파일 삭제, 브랜치 강제 push, DB 변경 등)
→ 반드시 사전 확인 후 실행

## 3. 근거 제시 규칙

다음 경우 반드시 근거를 먼저 밝힙니다:
- 새 패키지 추가 제안 시: 기존 스택으로 해결 불가한 이유
- 기존 패턴을 벗어나는 구현 제안 시: 왜 예외가 필요한지
- 아키텍처에 영향을 주는 변경 시: 영향 범위

## 4. 스킬 제안 기준

| 상황 | 제안할 스킬 |
| --- | --- |
| 코드 변경 후 품질 검토 요청 | `/review` |
| 기능 동작 전체 검증 요청 | `/qa` |
| 브랜치 머지 준비 완료 | `/create-pr` |

스킬은 맥락상 명확히 도움이 될 때만 제안합니다. 모든 작업에 붙이지 않습니다.

## 5. 코드 작성 규칙 요약

자세한 내용은 `.claude/conventions/` 참조.

- `any` 타입 금지 → `unknown` 또는 정확한 타입
- `useEffect`로 데이터 패칭 금지 → TanStack Query
- `React.FC` 금지 → function declaration + Props 인터페이스
- `fetch()` 직접 호출 금지 → `api.get/post/patch/delete`
- `../` 상대경로(디렉터리 경계) 금지 → `@/` alias
- `console.log` 커밋 금지 → `console.warn` / `console.error`
- API 응답을 Zustand에 저장 금지
- `src/types/api.ts` 수동 편집 금지 (openapi-typescript 자동 생성)
